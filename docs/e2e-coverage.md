# E2E workflow coverage matrix

Status in this matrix is evidence-based. `Pass` means the scenario passed in the complete verified run recorded below against the production build, real browser, clean isolated PostgreSQL database, real worker, real file storage, and without mocks of Fleetline internals.

Run `make test-e2e` for the complete browser suite and `make verify` for all release gates. The harness uses `POSTGRES_BIN_DIR` when supplied, otherwise a system PostgreSQL or the checksum-pinned PostgreSQL 16.15 build under `.tools/`; it uses the system Google Chrome channel. Each run creates a new database and media directory, applies migrations, seeds deterministic data, builds the production frontend, starts Gunicorn and the real worker, waits for readiness, runs Playwright, and cleans up services.

E2E output is under `artifacts/e2e/<UTC-run-id>/`: `playwright-report/`, `test-results/`, `results.json`, `logs/application.log`, `logs/worker.log`, `logs/postgres.log`, and `environment.txt`. Full verification writes its combined log, coverage, encrypted backup/restore evidence, durable-state comparisons, restored-process logs, and nested E2E evidence under `artifacts/verify/<UTC-run-id>/`.
